# monte carlo tree search 2

## two-player, turn-based, zero-sum games

Up to now we've been considering a single agent maximizing a single objective function, where the
net change to that objective function after every step is given by the reward function. It turns out
we can pretty easily extend MDPs to factor in more than one objective function. In the jargon of
game theory, I'll introduce a thing called a "two-player, turn-based, zero-sum game". Two-player
game means there are exactly two agents each maximizing their own objective functions. Turn-based
game means only one agent can take an action in a given state, and the rights flip with every
action. We will refer to this agent as the "side to move" of a state. Finally, zero-sum game means
that the gains of one agent equal exactly the losses of the other agent.

In particular, $\mathcal{S}, \mathcal{A}$, and $\mathcal{T}$ remain the same, except now each state
$s \in S$ also has a "side to move" associated with it. But now, we let $R(s, a, s')$ be the net
change to the objective function belonging to the _side to move of_ $s$ after taking action $a$ from
state $s$ and landing in state $s'$, which is the exactly the opposite to the net change of the
objective function belonging to the _side to move of_ $s'$, since the game is zero-sum. In other
words, zero-sum means that both players essentially have the same objective function, and one player
is trying to maximize it and the other player is trying to minimize it.

Naturally, the optimal policy $\pi^*(s)$ is the action which maximizes the expected value of the
objective function belonging to the _side to move of_ $s$. The associated Bellman equations is hence

$$
\pi^*(s) = \arg\max_{a \in \mathcal{A}(s)} Q^*(s, a)
$$

$$
V^*(s) = \max_{a \in \mathcal{A}(s)} Q^*(s, a)
$$

$$
Q^*(s, a) = \sum_{s' \in \mathcal{S}}\mathcal{T}(s, a, s')(\mathcal{R}(s, a, s') - V^*(s'))
$$

The only thing that changes is the negative sign in front of $V^*(s')$, representing the adversarial
zero-sum nature of the game.

## chess

For reasons we'll get into later, we want to represent [chess](2026-07-09-chess.md) as a MDP. Well,
chess is naturally a two-player, turn-based, zero-sum game. We can let each state
$s \in \mathcal{S}$ be a chess position. Actions $a \in \mathcal{A}(s)$ are legal chess moves. Chess
moves is deterministic, so transition probabilities $\mathcal{T}(s, a, s')$ are zero for all $s'$
except for one. For simplicity, denote this position as $s' = T(s, a)$. All we care about is the
final outcome, so rewards $\mathcal{R}(s, a, s')$ are zero except for when $s'$ is a terminal state.
If $s'$ is checkmate, than $\mathcal{R}(s, a, s')$ is $1$. If $s'$ is a draw, then
$\mathcal{R}(s, a, s')$ is $0$. The action value simplifies to

$$
Q^*(s, a) = \mathcal{R}(s, a, s') - V^*(s'), \quad s' = T(s, a)
$$

$V^*(s)$ can equal either -1, 0, or 1. $V^*(s) = 1$ if the side to move of $s$ has the ability to
force a win no matter the opponents moves. $V^*(s) = -1$ if the side to move of $s$ has no ability
to prevent a loss if the opponent makes the right moves. $V^*(s) = 0$ if neither is true.

### why?

I promised I'd answer the question: "why do we want to formulate chess as a MDP?". The answer is,
because we want to use [monte carlo tree search](2026-07-12-mcts.md) to compute the best move! Well,
if you're a smart guy/gal, you'd ask: "why do we want to use monte carlo tree search to compute the
best move?"

### minimax search

If you look at the Bellman equation for chess, it's quite simple. In fact, there's no "expectation"
to even compute! It's merely a matter of considering all sequences of legal moves, and checking
whether or not a player can force a win. One could program an exact solution to this MDP with
something like

```python
def compute_value(pos):
    if is_checkmate(pos):
        return -1
    if is_draw(pos):
        return 0
    value = float('-inf')
    for move in legal_moves(pos):
        next_pos = make_move(pos, move)
        value = max(value, -compute_value(next_pos))
    return value
```

However, if you know anything about chess, you'd know that the number of sequences of legal moves is
astronomically large for most positions. What one can do is create a heuristic function which
outputs a number in $[-1, 1]$ which is a guess for the value of the current position. It is allowed
to be outside of -1, 0, and 1 to allow for uncertainty. The closer the heuristic is to 1 the closer
the position should be to being winning for the current side to move, and vise versa. This heuristic
is usually hand-coded by experts in chess to take into account things like number of pieces left on
the board amd their locations. The idea is that this heuristic should be more and more accurate the
closer the position is to being terminal. If you consider sequences of moves of a certain length
(which can be manageable in size), you can assign their terminal value with the heuristic. Then the
deeper you search, the more accurate your final result should be.

```python
def compute_value(pos, depth):
    if is_checkmate(pos):
        return -1
    if is_draw(pos):
        return 0
    if depth == MAX_DEPTH:
        return heuristic(pos)
    value = float('-inf')
    for move in legal_moves(pos):
        next_pos = make_move(pos, move)
        value = max(value, -compute_value(next_pos, depth + 1))
    return value
```

This idea is known as [minimax search](https://chessprogramming.org/Minimax) and it is exactly how
essentially all dominant chess engines worked for the majority of computer science history.

### deep neural networks

In 2012 with the release of [AlexNet](https://en.wikipedia.org/wiki/AlexNet), deep neural networks
began to become the dominant force in artificial intelligence. In fact, with a big enough dataset of
previously analyzed chess position, once can easily train a deep neural network that greatly
outperforms any hand-coded heuristic function from the previous section in terms of accuracy.
However, at least two things go wrong if one attempts a replacement:

1. There is a massive tradeoff with speed. Deep neural networks are typically much more
   computationally intensive than hand-coded heuristic, so the number of positions analyzed must be
   cut down greatly. In minimax search this means that the depth must be decreased.

2. Deep neural networks are inherently noisy. Minimax search computes the exact maximum at every
   step, meaning that one single noisy evaluation in the wrong line could throw the algorithm off
   the best move.

I propose that [monte carlo tree search](2026-07-12-mcts.md) is much more compatible with these two
things. Look at step 3 in the algorithm at the top of this post, simulation. It should well agreed
upon that such a random rollout is already quite computationally intensive and highly variable.
Suppose that one replaced such a rollout with a neural network that predicts the expected result,
similar to the way we used a heuristic in minimax. Then:

1. Since we are greatly limited in our search, common sense would say to spend more time considering
   sequences of moves that are likely to be played on the board. Minimax search considers all
   sequences to roughly the same depth. Monte carlo tree search naturally searches the most
   promising sequences the deepest due to to the UCB metric.

2. In monte carlo tree search, action values are taken as the average of the reward estimates
   evaluated stemming from a particular move. Therefore the inherent noise from the deep neural
   network is almost completely averaged away.

### policy + upper confidence bound

While it's true that monte carlo tree search is naturally good at spending more time searching
promising variations, its also true that often quite a large number of iterations is needed before
the algorithm starts to do this. At the beginning of the search, all of the exploration terms are
high, and hence bad moves are searched almost as much as good moves are.

Since every expanded node gets fed into a deep neural network initially, it's cheap to add a _policy
head_ which outputs a probability distribution $P(s, a)$ over the legal moves $a \in A(s)$,
predicting the actions that are likely to be good. If we penalize the exploration terms of low
probability moves, then we tend to get our desired behavior more quickly, then the algorithm is more
efficient. Initially introduced in a paper called
[Multi-armed Bandits with Episode Context](https://link.springer.com/article/10.1007/s10472-011-9258-6)
and reformulated in the [AlphaZero](https://arxiv.org/abs/1712.01815) paper, was a reformulation of
the upper confidence bound called the Policy + Upper Confidence bound for Trees (PUCT)

$$
PUCT(s, a) = Q(s, a) + c_{\text{puct}}P(s, a)\sqrt{\frac{\ln(N(s))}{N(s, a)}}
$$

#### algorithm

An algorithm to implement monte carlo tree search with PUCT for chess would look like this. We store
the tree in memory, which grows in size as the algorithm runs. Each node in the tree stores the
following information:

- $N(s)$, the number of simulations which reached node $s$, initialized to 0.
- For all actions $a$ from node $s$: $N(s, a)$, the number of times action $a$ was taken from node
  $s$ over all simulations, initialized to 0.
- For all actions $a$ from node $s$: $Q(s, a)$, the empirical average action value over all
  simulations, initialized to 0.
- $V(s)$, the estimated value of $s$, computed by the deep neural network when the node is
  initialized.
- For all actions $a$ from node $s$: $P(s, a)$, the policy value of action $a$, computed by the deep
  neural network when the node is initialized.

The tree starts out as only the root node. Repeat the following steps until time runs out:

1.  **Selection:** Start from the root node $s$. If any action from $s$ is unexplored, choose the
    one with the highest policy value. If all actions from $s$ have been explored, then let

    $$
    a^*(s) = \arg\max_{a} PUCT(s, a)
    $$

    and take action $a^*(s)$. After taking $a*(s)$ you reach a new state $s'$. Repeat this selection
    process until an unexplored state is reached.

2.  **Expansion:** If an unexplored state $s_T$ is reached, then add it to the tree.
3.  **Backpropagation:** For each state action pair $(s_i, a_i)$ in the traversal leading to $s_T$,
    preform the following updates

    $$
    N(s_i) \leftarrow N(s_i) + 1
    $$

    $$
    N(s_i, a_i) \leftarrow N(s_i, a_i) + 1
    $$

    $$
    Q(s_i, a_i) \leftarrow Q(s_i, a_i) + \frac{V(s_T) - Q(s_i, a_i)}{N(s_i, a_i)}
    $$

Once you are done searching, choose the action $a$ such that $Q(s, a)$ is the highest.
