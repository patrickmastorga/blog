# monte carlo tree search

## markov decision processes

Let's set up a simple model for the world and investigate how one might make optimal decisions. Our
model will be discrete. Let's represent the set of all possible _states_ in our model as
$\mathcal{S}$. For some state $s \in \mathcal{S}$, let $\mathcal{A}(s)$ be the set of all available
_actions_ in that state. Taking an action from one state leads us to a new state. For
$s, s' \in \mathcal{S}$ and $a \in \mathcal{A}(s)$, Let $\mathcal{T}(s, a, s')$ be the _transition
probability_ of reaching state $s'$ after taking action $a$ in state $s$. Let
$\mathcal{R}(s, a, s')$ be the _reward_ gained after such a transition. For simplicity, let's assume
that every sequence of actions eventually reaches a terminal state (a state $s$ such that
$\mathcal{A}(s)$ is the empty set) and hence there is no way to accumulate infinite reward. We call
the tuple $(\mathcal{S}, \mathcal{A}, \mathcal{T}, \mathcal{R})$ a _Markov Decision Process (MDP)_.

An _optimal decision rule_ is a mapping from every state $s \in \mathcal{S}$ to an action in
$\mathcal{A}(s)$, such that following the optimal decision rule for every state you visit in a
traversal maximizes the expected cumulative reward of the traversal. For an MDP like ours, this is
simply a lookup table and we'll denote it as $\pi^*(s)$. To us explain our optimal decision rule,
we'll define associated functions called _values_ and _action values_. The value of a state $s$ is
the expected cumulative reward from following our optimal decision rule starting from state $s$. It
is denoted by $V^*(s)$. The action value of an action $a$ in a state $s$ is expected cumulative
reward we get from following our optimal decision rule starting from state $s$, provided we take
action $a$ first. It is denoted by $Q^*(s, a)$. It should be relatively clear that

$$
\pi^*(s) = \arg\max_{a \in \mathcal{A}(s)} Q^*(s, a)
$$

$$
V^*(s) = \max_{a \in \mathcal{A}(s)} Q^*(s, a)
$$

$$
Q^*(s, a) = \sum_{s' \in \mathcal{S}}\mathcal{T}(s, a, s')(\mathcal{R}(s, a, s') + V^*(s'))
$$

For your curiosity, this is the
[Bellman equation for MDPs](https://inst.eecs.berkeley.edu/~cs188/textbook/mdp/solve.html#421-the-bellman-equation).

If we can compute $Q^*(s, a)$ for every possible pair $(s, a)$ of state and action in our MDP, then
we know the optimal decision rule. However, even from a glance, it should be clear that computing
these action values is very hard. To know $Q^*$, we must find $V^*$. But to find $V^*$, we must know
$Q^*$! If your interested in one way to solve this problem, I encourage you to look at the
[Value Iteration Algorithm](https://inst.eecs.berkeley.edu/~cs188/textbook/mdp/value-iteration.html).
However, value iteration requires you to loop over every single tuple $(s, a, s')$ of state, action,
and resulting state in the entire MDP many times. For larger MDPs, the computation time is massive.
Furthermore, you must wait for the algorithm to finish entirely before reasonably concluding even a
single optimal decision rule. This is because value iteration solves the MDP entirely, finding every
optimal decision rule simultaneously.

## what is monte carlo tree search?

_Monte Carlo tree search_ is an algorithm for finding the optimal decision rule for a given starting
state $s$. To make the computation tractable, the algorithm takes two major shortcuts:

1.  The algorithm only computes the action values for states and actions which you can actually
    reach from the starting state $s$, hence why the algorithm is formally known as a _tree search_.
    For many MDPs, this cuts down the number of values we need to compute immensely.
1.  The algorithm uses random sampling to estimate expectations of cumulative reward, hence why this
    algorithm is formally knows as a _Monte Carlo_ tree search. In general, Monte-Carlo methods use
    random sampling to estimate complex expectations which are intractable to solve exactly.

To explain, let's suppose that we know the optimal decision rule for our MDP. Then the Monte Carlo
way to compute $Q^*(s, a)$ would be to start at state $s$ and take action $a$. Then, keep taking
actions according to the optimal decision rule until termination, keeping track of the total
accumulated reward. Repeat this process of running a full simulation hundreds, or thousands, or
millions of times. The average total accumulated reward over all simulations converges to the true
value of $Q^*(s, a)$.

But we don't know the optimal decision rule! How can we randomly sample from a distribution that we
don't actually know yet? We need to devise a new sampling strategy which may start off wrong, but
eventually corrects it's course and converges to the correct one. The correct way to sample is: "at
every step choose the action which grants us the highest total expected cumulative reward". The
sampling method that we will construct will be, informally, "choose the action based on a strategy
which gets us as close to the highest total expected cumulative reward without knowing which action
grants us this upfront". As the number of trials increase, this strategy will eventually always pick
the optimal action, and hence we still converge to the correct value. Most importantly, this
strategy minimizes the error on its way to convergence. We borrow this strategy from a famous
problem in reinforcement learning.

## The multi-armed bandit problem

Suppose that you have a large number of coins and you enter a room with multiple slot machines
(endearingly known as "one-armed bandits"). You know nothing about the expected payout of the slot
machines. Some slot machines could have higher expected payouts than other slot machines. How do you
maximize your expected total payout? Well, we wan't to play the slot machine with the highest
expected payout as many times as possible!

At a given step, we can compute the empirical average of the payout each slot machine observed so
far. A reasonable strategy would be to choose the slot machine which the highest average payout,
right? But if we have only played a certain slot machine a small number of times, then the average
payout might be far from the expected payout. Lets devise a better metric than the average. At a
given step, set some probability threshold $p$, which should be small. Then, for each slot machine,
compute an estimate for the expected payout of said slot machine such that the probability of the
_true_ expected payout being higher than the estimate is at most $p$. Therefore if we reject a slot
machine based on this estimate, the probability of falsely rejecting that slot machine is at most
$p$.

We can construct such an estimate using _Hoeffding's Inequality_. Let $X_1, X_2, \ldots, X_n$ be a
sample of $n$ payouts from a given slot machine. Let $\overline{X}$ be their average and
$\mathbb{E}[X]$ be the true expected payout. Finally, assume that each payout is bounded in the
range $[a, b]$. Then

$$
\mathbb{P}(\mathbb{E}[X] > \overline{X} + t) \leq \exp\left(-\frac{2nt^2}{(b - a)^2}\right)
$$

If we set the right hand side equal to $p$ and solve for $t$ we get

$$
t = (b - a)\sqrt{\frac{-\ln(p)}{2n}}
$$

and now we have the estimate we are looking for.

Finally, we need a way to set the value of $p$. Recall that $p$ is the bound on the probability of
falsely rejecting a slot machine. This should relate to the number of tokens we have spent. If we
have only spent a few tokens, then the total uncertainty is high and it is okay if we falsely reject
a slot machine to make room for one which has proved more lucrative so far. However, if we have
spent a large number of tokens, we want to be absolutely sure that we have found the true optimal
slot machine. A paper called
[Finite-time Analysis of the Multiarmed Bandit Problem](https://homes.di.unimi.it/~cesabian/Pubblicazioni/ml-02.pdf)
proved that setting $p = N^{-4}$, where $N$ is the number of tokens spend so far, is optimal, and
that the resulting estimate

$$
UCB_i = \overline{X}_i + (b - a)\sqrt{\frac{2\ln(N)}{n_i}}
$$

called the _Upper Confidence Bound (UCB)_, yields the optimal algorithm for maximizing profit. Not
only does this maximize profit, but the expected payout approaches the maximum asymptotically. This
metric naturally mimics the reinforcement learning principle of "exploration + exploitation". The
term $(b - a)\sqrt{\frac{2\ln(N)}{n_i}}$ is known as the _exploration term_ as it boosts the score
of machines that have received less tokens so far. $\overline{X}_i$ is known as the _exploitation_
term, as it boosts the score of machines that have proven more lucrative so far.

## the monte carlo tree search algorithm

For each action $a$ from out root state $s$, $Q^*(s, a)$ is the maximum expected cumulative reward
received after taking action $a$. Once way of computing this is by sampling traversals following the
optimal decision rule at each step. Another way of computing this is by sampling traversals choosing
the action with the highest UCB estimate of its action value at each step. The first method requires
us to know the optimal decision rule upfront, but the second does not. All the math used in the
previous section guarantees that the second method converges to the first as quickly as possible.

An algorithm to implement monte carlo tree search would look like this. We store the tree in memory,
which grows in size as the algorithm runs. Each node in the tree stores the following information:

- $N(s)$, the number of simulations which reached node $s$, initialized to 0.
- For all actions $a$ from node $s$: $N(s, a)$, the number of times action $a$ was taken from node
  $s$ over all simulations, initialized to 0.
- For all actions $a$ from node $s$: $Q(s, a)$, the empirical average action value over all
  simulations, initialized to 0.

The tree starts out as only the root node. Repeat the following steps until time runs out:

1.  **Selection:** Start from the root node $s$. If any action from $s$ is unexplored, choose one at
    random and take it. If all actions from $s$ have been explored, then let

    $$
    a^*(s) = \arg\max_{a} \left( Q(s, a) + c_{\text{ucb}}\sqrt{\frac{\ln N(s)}{N(s, a)}} \right)
    $$

    and take action $a^*(s)$. This is the exactly Upper Confidence Bound (UCB). After taking $a*(s)$
    you reach a new state $s'$. Repeat this selection process until an unexplored state is reached.

2.  **Expansion:** If an unexplored state is reached, then add it to the tree.
3.  **Simulation:** From the unexplored state, select actions at random until the a terminal node is
    reached. You should now have a full traversal of state action pairs and rewards starting from
    the root node.
4.  **Backpropagation:** For each state action pair $(s_i, a_i)$ in the traversal, preform the
    following updates

    $$
    N(s_i) \leftarrow N(s_i) + 1
    $$

    $$
    N(s_i, a_i) \leftarrow N(s_i, a_i) + 1
    $$

    $$
    Q(s_i, a_i) \leftarrow Q(s_i, a_i) + \frac{R_i - Q(s_i, a_i)}{N(s_i, a_i)}
    $$

    where $R_i$ is the total accumulated award _after_ state $s_i$ is reached.

Once you are done searching, choose the action $a$ such that $Q(s, a)$ is the highest.
